# 원본 이식판 개발 기준

## 목표와 범위

원작의 계산·분기·대기·난수·상태 변경을 Dart로 재현합니다. 원작 그래픽을 고정 사용하며
게임 규칙·수치 범위 변경은 동등성 검증 뒤 별도 검토합니다.

판정 근거는 이 프로젝트 내부의 `repo_source/LORE_1993_src/`와
`repo_source/LORE_1993_runtime/`입니다. 기존 Dart 코드와 테스트는 재사용 후보이며
원본 동작의 정답으로 간주하지 않습니다. DARK·MYST 및 치트/제작 도구는 본편에서 제외합니다.

맵 표시·터치·키보드·오디오·파일 접근은 플랫폼 어댑터로 구현합니다.
앱 설정과 그래픽 스킨 전환은 제공하지 않습니다.

## 실행 로직의 소유권

원본 Pascal의 완전한 프로시저 또는 선택·전투 후속까지 닫힌 분기를 직접 이식합니다.
호출 순서·조기 종료·난수 소비·지도 쓰기·선택 취소·승리/도주/패배 후 재개를 보존합니다.
한 사건은 하나의 런타임 처리기만 소유합니다. 조건이 거짓인 무동작도 결과이므로
다른 처리기를 실행해 보상이나 사건을 대신 발생시키지 않습니다.

실행용 JSON 이벤트 규칙과 legacy fallback은 제거된 구조입니다. JSON은 자원·저장에
사용할 수 있으며 과거 parser/규칙 fixture는 테스트용 자료입니다. 직접 Dart 절차의
효과 전달 모델인 `ScriptStep`·`ScriptRun`을 JSON 규칙 엔진으로 해석하지 않습니다.

## 비트·정수·배열 계약

- `LORESUB.PAS:11-79`: 능력치·장비·좌표·식량·etc는 byte,
  HP/SP/ESP·의식불명·사망은 16-bit integer, 금화·경험치는 32-bit longint다.
  계산식의 중간 결과 자료형과 대입 시 저장 폭을 구분한다. 식량에 원본이
  명시한 255 상한이 있으면 그 조건을 보존하며 모든 계산에 clamp를 넣지 않는다.
- `etc`는 비트 플래그만이 아니다. 타이머·설정·퀘스트 단계·방 번호와 비트가
  함께 저장된다. 예를 들어 `LORESPEC.PAS:1415/1436`은 `etc[40]`에
  `(random(7)+1) shl 1`로 방 번호를 넣고 `shr 1`로 되읽는다.
  이름 있는 Boolean으로 치환하면 상위 값과 하위 비트의 관계를 잃는다.
- `encounter := @party.etc[7]`, `maxenemy := @party.etc[8]`
  (`LORESUB.PAS:1794-1795`)은 같은 바이트의 별칭이다. UI 설정을 따로
  복사해 두면 다음 로직에서 값이 달라질 수 있으므로 동일 저장소 접근자로 연결한다.
- 원본 `map[1..100,1..100]`은 `map[x,y]`, 화면 격자는
  `grid[y-1][x-1]`이다. 파일은 `y` 바깥 루프, `x` 안쪽 루프로 읽고 쓴다.
  `player/enemy[1..7]`, `battle[1..6,1..3]`, `accuracy/level[1..3]`도
  배열별 범위와 사용 슬롯을 따로 보존한다. 빈 슬롯과 임시 7번 슬롯을 압축하지 않는다.
- `div`는 0 방향 정수 나눗셈, `mod`는 피제수 부호의 나머지다. Dart
  `%`로 음수 Pascal `mod`를 대체하지 않는다. 비트 연산과 비교·논리 연산은
  괄호로 원본 우선순위를 명시한다.
- 원본 소스에 범위/오버플로 지시자가 명시되지 않은 곳의 EXE 컴파일 옵션은
  미확인이다. etc 저장은 unchecked byte의 하위 8비트를 보존한다.
  `LorePascal`의 word/integer/longint 변환은 준비된 계약이며 다른 게임 필드에
  일괄 적용하지 않는다. 실제 경계 동작은 DOS 실행이나 컴파일 결과와 대조한 뒤 연결한다.
- 범위 밖 배열 접근의 DOS 메모리 손상은 에뮬레이션하지 않고 실패로 드러낸다.
  잘린 MAP 파일에 임의 벽을 채우지 않는다. 이는 잘못된 입력의 명시적 처리 차이다.

자료형과 div/mod 의미는 Borland의
[Turbo Pascal 7 Language Guide](https://turbopascal.org/wp-content/uploads/Turbo_Pascal_Version_7.0_Language_Guide_1992.pdf)
25-26, 69, 211-213쪽을 참고한다. 이 자료가 원본 EXE의 컴파일 옵션이나
중간 계산 결과를 증명하지는 않는다.

`tool/audit_source_memory.py`가 도달 가능한 게임 유닛의 위험 연산·배열·지도
쓰기 위치를 `docs/audits/source_memory_audit.md`에 모은다. 문자열과 주석은
기존 감사 도구로 제외하고 원본 파일 해시와 행을 유지한다. 이 색인은 피연산자
자료형 추론이나 완전한 컴파일러 감사가 아니며, 암묵적 with 별칭과 중간
오버플로 등은 프로시저 대조에서 추가 검토한다.

## 실행 순서와 검증

| 단계 | 작업 | 확인할 경계 |
| --- | --- | --- |
| 1 | 상태·수치·배열·지도·저장 | 원본 자료형, raw byte, 별칭, 저장 왕복 |
| 2 | 이동·입장·대화·특수 사건 | 실제 타일 진입, 조건 양쪽, 지도 변경, 재방문 |
| 3 | 전투·메뉴·시설·생성·엔딩 | 난수, 계산 경계, 취소, 승리/도주/패배 후속 |
| 4 | 화면·입력·오디오 어댑터 | 기본 앱 동작과 원작 재생 경로를 각각 확인 |
| 5 | 새 게임부터 엔딩·재시작 | 주요 대체 경로와 저장 이후 다음 행동 |

난수는 같은 입력 스트림의 호출 순서·횟수·상한·갱신 seed를 비교합니다.
원작 저장은 난수 seed를 기록하지 않으므로 저장 재개만으로 같은 난수열을 가정하지 않습니다.
원본 추출 fixture, 독립 실행 근거와 실제 앱 진입점 검사를 함께 사용합니다.

## 최종 완료 게이트

- 도달 가능한 파일·루틴·분기·지도 쓰기·자료가 분류되고 원본 조건, 이식 처리기,
  독립 근거와 검증에 연결되어야 합니다. 부분 근거를 완료로 세지 않습니다.
- 미해결 동작 차이가 없어야 합니다. 미확인 컴파일 옵션과 의도적인 플랫폼 차이는
  이유·영향·검증을 명시하며, 원본 버그로 추정되는 조건도 근거 없이 고치지 않습니다.
- 27개 지도 ID의 진입·거절·출구·사건·대화·동적 변경·재방문과 공통 게임 규칙을
  대조합니다. 모든 좌표와 모든 상태의 곱집합보다 닫힌 절차와 실제 호출 경로를 검사합니다.
- 새 게임 → 엔딩, 주요 대체 경로, 저장·불러오기 이후 진행을 헤드리스 재생과 실제
  앱에서 확인합니다. 다음 행동과 UI·입력·음악·효과음의 대응도 확인합니다.
- 관련 원본 재생, 전체 Flutter 테스트, 분석, 추출기 검사, 자료 무결성 및 웹/출시
  대상 릴리스 빌드가 통과해야 합니다. 실패·제외 검사는 통과로 기록하지 않습니다.

[계약 장부](../audits/contract_ledger.md)와 [완료 공백](../audits/completion_gaps.md)은
등록·근거 연결 색인입니다. 분기 수, wrapper 수, 테스트 통과만으로 전체 완료를 선언하지 않습니다.
보고서와 검증 명령은 [문서 안내](../README.md)를 따릅니다. 이 문서에 작업 이력을 누적하지 않습니다.
