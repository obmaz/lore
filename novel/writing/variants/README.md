# 문체별 본문 레이어

[공용 A/B 기준](../styles.json)을 매 집필 전에 읽는다. A 정의는 기존 `project.json#/style`을
참조하며 현재 원고는 그대로 A다. B 정의는 `styles.json#/profiles/B`이며 빠른 호흡·행동과
판단 중심의 웹소설형 산문이다. 특정 작품의 문장·설정·시스템을 복제하지 않는다.

현재 A는 1~3장, B도 1~3장 초고다. 문체·의미·출판 승인은 별도 검토 대상이다.
[B안 교정 기록](B/copyedit-review.json)은 지시 대상·동작 순서·중복 귀환과 띄어쓰기 검토 범위를
기록한다. 1차 교정은 B 본문 97개 블록과 공통 대사를 검토했다. 2차 교정은
B 문체 revision 2를 1~3장에 적용하고, 문장 호흡·내용 연결·문법·행동 순서를 다듬었다.
`passes`에는 변경 블록과 장면 순서 점검, 참고용 문장 길이 측정이 있다.
짧은 대화·긴장 문장은 유지하며 문장 수치가 문학적 완성도나 승인을 뜻하지 않는다.
공통 대사의 읽기용 교정은
`../script-overrides/registry.json`에서 A/B에 함께 적용한다. 보존 원문·공통 분기·A 창작 본문은
바꾸지 않았다. 구조 검사와 집필 교정이 정사·출판 승인을 뜻하지는 않는다.
[B 1장](B/chapter01.json)은 기존 274개와 귀환 전투의 조건부 문단 20개, 총 294개 창작 블록에
별도 본문을 제공한다. 3차 편집은 B 1장의 인사·탐색·장비 준비·귀환·보고를 검토했다.
금화는 발견 동기와 운반 부담으로, 무기고 정비는 귀환길 멧돼지 조우에서의 움직임으로 이어진다.
전투·임시 지형·손질은 `authored/proposed` 창작이며 원작 고정 사건이나 장비의 새 능력이 아니다.
공통 오버레이에 실제 동행·현재 무기·방패 담당자·방문 이력을 검사하는 산문 자리를 두고,
A는 그 자리의 본문을 비워 기존 산문을 보존한다. 빈 본문은 웹/EPUB에서 문단을 만들지 않는다.
방패 담당자는 양손으로 방어하며 그 사람의 양손 무기 행동은 표시하지 않는다. 방패가 없으면
바위 옆으로 회피한다. 활의 탄약·새 주문·전투 보상·부상·금화 손실은 가정하지 않는다.

4차 재집필은 B 1장의 **인정 욕구 → 탐사 성공과 방심 → 오판으로 생긴 위기 → 도움 요청과
공동 회피 → 잘못까지 밝히는 보고**를 연결한다. 시작 일행은 원래 친한 사이이며,
낯선 장소에 대한 긴장과 친구끼리의 익숙함을 구분한다. 사용자 지정 친분은 공용 인물
설정·관계에, B의 심리와 대화·단계별 원인/결과는 교정 기록의
`passes[id=chapter01-dramatic-arc-04].dramatic_arc`에 둔다. 선택한 탐색·금화·정비는
해당 경로에서만 이 흐름에 참여한다. A 및 B 2~3장 산문은 이번 재집필 범위가 아니다.
[B 2장](B/chapter02.json)은 창작 블록 77개, [B 3장](B/chapter03.json)은 70개를 별도로 집필한다.
3장에는 준비와 부상·영입/교체·치료 후 작별/거절·봉인 발견/미해제·보고가 포함된다.
동료와 식량·마법 자원·축복의 조건은 공통 계약을 그대로 따르며 서로 다른 응답을 섞지 않는다.
[연결 인덱스](B/series.json)는
집필한 순서의 장 ID와 파일 참조만 기록하며 공통 목차·사건·분기를 복제하지 않는다.
이것은 독립 분기 그래프나 새로운 게임 데이터가 아니다. `tools/prose_variants.py`는 검증된
A의 집필한 장을 읽고 각 장의 블록 `text`와 창작 메모만 바꾼다. 제목·노드·조건·원작 인용·선택·효과·공개·
동료·장비는 공유한다. 인물·무기·지명은 같은 안정된 `ref`를 사용하므로 개명이 양쪽에 반영된다.

`base_source_sha256`는 검토한 원고를 고정한다. 첫 장은 원고·오버레이, 후속 장은 해당 퀘스트·
연속성 계약·공통 장 연결의 해시다. 공통 사건이나 A 원고가 바뀌면
생성이 중단된다. 변경을 B에 대조한 뒤에만 해시를 갱신한다. `style_revision`이 달라도 중단된다.
누락 블록·원문 인용의 덮어쓰기·모르는 ID·다른 장 블록의 주입·중간 장 건너뛰기·중복 인덱스를 거부한다.
B 미집필 장을 A 본문으로 채우지 않는다. 장별 파일이 모두 있어도 인덱스에 연결하지 않은 장은 읽기본에 넣지 않는다.
공통 골격이나 분기 변경이 필요하면 먼저 원래 원고·계약에서 검토한다.

후속 B 장은 `prose.schema.json`의 공용 레이어 형식을 사용한다. `chapter_id`는 공통 장 ID,
`chapter_limit`는 그 장의 번호다. 모든 창작 블록을 집필하고 해당 장의 의존 해시를 검토한 뒤
`B/series.json`과 `styles.json#/profiles/B/written_chapters`에 같은 연속 장 목록을 등록한다.
현재 B 문체는 revision 2이며 각 장과 연결 인덱스의 적용 revision이 같아야 한다.
장만 추가할 때는 문체 revision을 유지하고, 공용 문체가 바뀌면 적용 장을 재검토해
명시적으로 갱신한다. 기존 B 장을 자동 재집필하지 않는다.

읽을 판본에는 A와 B 두 개만 나온다. `/novel/`의 선택 화면은 기본 A이며
`?edition=B`로 B에서 시작할 수 있다. 판본을 바꾸면 처음부터 읽는다. 경로 저장의
fingerprint가 달라 다른 판본의 경로 파일을 무심코 불러오지 않는다. 두 HTML 모두 외부 요청과
작가용 마스터 없이 오프라인으로 동작한다. 제작실의 목차·장별 그래프는 하나를 공유한다.

```bash
python tools/prose_variants.py
python tools/writing.py validate
python tools/writing.py export
python tools/writing.py export --check
```
