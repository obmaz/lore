# 집필 작업 지침

이 파일은 **집필 작업의 제약**만 추가한다. 현재 원고·판본·수정 파일과 명령은 README에,
공통 메타데이터·참조 규칙은 상위 AGENTS에 둔다. 같은 내용을 별도 규칙으로 재정의하지 않는다.

상위 `../AGENTS.md`를 따른다. 구성·파일 역할·현재 범위·명령은 [README.md](README.md),
원고 조건/효과는 [공용 형식](../authoring/README.md), 공개 정책은
[인물 지침](../characters/AGENTS.md)을 기준으로 한다. 아래는 집필 시 지켜야 할 제약이다.

## 구성과 작업 단위

- 매 집필·재집필 전에 `project.json`의 `viewpoint`, `tone`, `style`을 읽고 따른다.
  문체의 단일 원본은 이 파일이며 별도 지침에 문체를 복제하지 않는다. 골격 작업은
  `style.stage_policy.outline`, 상세 산문은 `style.stage_policy.prose`를 적용한다.
  인계 메모에 적용한 `style.revision`을 기록한다. 기준을 바꿔도 기존 원고는 자동 재집필하지 않는다.
- 공용 `templates/`로 큰 구성 → 큰 이야기 검토 → 소단락 주요 내용 → 의미 있는 분기 →
  장면·소편 → 본문 순으로 작성한다. 전체 세부 문장을 미리 확정하지 않는다.
- 기본 작업량은 한 소편이다. 여러 소편을 명시적으로 요청하지 않으면 한 소편을 집필하고
  피드백 후 이어간다. 긴 소편은 공백 포함 약 3,500~6,500자를 출발 목표로 하며 반복으로 채우지 않는다.
- 감각·행동·대화와 작은 변화를 충분히 쓴다. 미정 설정·조건 검증·보류 설명은 산문 대신 메모에 둔다.
- 장 제목·필수 메인 사건은 `storyboard/chapters.json`에서 참조한다. 모든 메인 장·핵심 사건은 필수다.
  미집필 장은 `outline_only`, 장면 참조는 `null`이다. 선택 방문의 필수 채택은 편집 추가로 표시한다.
- 큰 이야기의 인과는 상황·목표·수행·결과·다음 행동으로 쓴다. 설명을 들은 시점과 실제 능력·
  계급·열쇠를 얻은 시점을 분리한다. 원문 구간은 `source_section_refs`, 주의는 `continuity_limits`다.
- 소단락은 하나의 목적·수행·결과가 있는 묶음이다. 필수 사건은 `completes_beats`로 한 번씩 배치하고,
  부모 `macro_revision` 변경 시 재검토한다. `reading_next`와 논리 선행 `after`를 혼동하지 않는다.
- 병렬 목표는 순서가 자유여도 모두 필수다. 후보 `carry_keys`를 이미 구현한 상태로 표시하지 않는다.
  상세 집필과 원문 반영표 연결 전에는 실행 완료·본문 완성으로 표시하지 않는다.
- 출판용 목차 트리·흐름도는 `publication/flow.plan.json`과 공용
  `templates/publication-flow.template.json`을 입력으로 생성한다. 제목·본문·분기는 원래 JSON을
  참조하며 도식을 별도 이야기 원본으로 만들지 않는다. 트리의 소속과 실제 진행을 구분한다.
  병렬 순서는 문맥별 복제 노드로 표시해 거짓 반복·순환을 만들지 않는다. 선형 출판 순서는
  실제 선택 경로를 재생하며 예시 경로를 정사·출판 승인으로 취급하지 않는다. 미집필 본문·
  페이지는 미정으로 두고 전편 도식은 작가용 스포일러로 관리한다. 생성 JSON/MD/SVG를 직접
  수정하지 않으며 수동 변경은 보존한 뒤 입력으로 옮긴다.
- `studio/`는 작가 전용 통합 조회 화면이다. 기존 원고·설정·구조를 참조한 생성 스냅샷이며
  별도 이야기 원본·자동 저장·출판 승인으로 취급하지 않는다. 원본 JSON의 위치를 연결하고
  판본·집필 단계·창작/추론 표시를 보존한다. 전편 자료를 독자용 `/novel`에 포함하지 않는다.

## 본줄기와 분기

- 전 장에 같은 정방향 원칙을 적용한다. 하나의 갈림길에서는 한 경로만 고르고 다음 본줄기로
  합류한다. 완료한 갈림길로 되돌려 다른 선택 결과·금화·장비·동료 장면을 수집하게 하지 않는다.
  확인·발견·완료처럼 단일 진행만 있는 소단락은 자동 연결하고 선택 버튼을 만들지 않는다.
  실제 장착 여부·담당자·접근법·동행처럼 결과가 달라지는 결정만 선택으로 남긴다.
  다른 결과를 읽는 것은 독자의 명시적인 이전 선택 되돌리기/처음부터 재독에서만 가능하다.
  원작 재전투는 별도의 실제 재시도 사건으로 구분하고 같은 갈림길의 결과 수집으로 쓰지 않는다.

- 선택은 장면을 읽은 뒤 실제 행동·접근법·증언 경험·동료·장비·후속 반응이 달라질 때 둔다.
  인사·조회·대사 한 줄마다 선택하지 않는다. 거절→다시 생각→원래 자리 같은 무의미한 우회는
  연속 산문이나 자동 연결로 합친다. 자동 연결도 경로 ID로 기록하되 독자의 선택으로 표시하지 않는다.
- 기본은 하나의 경로로 앞으로 흐르는 구성이다. 자유 탐방·되돌아보기는 서사상 이유가 있을 때만 제한한다.
  배타 응답 재배치는 서로 다른 질문/시점임을 산문으로 밝히고 창작 각색·조건을 표시한다.
- `main_story`의 장면 순서와 첫 방문 필수 블록을 지킨다. 필수 사건을 탐방·영입 여부에 묶거나
  다음 본줄기 전에 종료하지 않는다. 상태 값만 올려 읽은 장면을 대체하지 않는다.
- 분기는 다음 본줄기 전에 합류한다. 공유 장면의 출구에는 실제 임무 단계 조건도 붙인다.
  재방문 요약은 허용하되 첫 방문 필수 본문 표시 이력을 선택 경로에서 재구성한다.
- 실제 분기는 조건·동행/장비·효과·선택 뒤 본문·합류·후속 반응을 함께 정의한다.
  `authority: main`의 열쇠·봉인·계급·필수 지식은 본줄기 사건만 기록하며 선택 효과로 선지급하지 않는다.
- 역할은 실제 동행과 현재 소유/장착 장비로 검사한다. 영입 경험은 현재 동행이 아니다.
  효과는 원자적으로 적용하고 자료형·동료 자리·장비 소유를 지킨다. 병렬 블록은 모든 순열만 허용한다.
- 저장은 판본 지문과 선택 ID로 재생한다. 임의 상태·진도, 반복 보상·미래 선택·본줄기 건너뛰기를 거부한다.
  가능한 선택이 하나면 자동 처리한다. 작가용 전편 분기를 기존 첫 장 독자 저장으로 자동 승격하지 않는다.

## 원문·설정·연속성

- 제목·본문·대사·선택지의 이름·장비·마법·지명은 구조화된 `ref`를 쓴다. 안정된 ID를 개명하지 않는다.
  인물은 `writing_overrides`를 우선 적용하고 없는 값만 기존 카드로 되돌아간다. 대체값은
  `../reference/analysis.json`, 기존 표시명은 `../reference/names.json`에서 관리한다.
  이름 문자열 복사·치환·`reference_text` 해제로 우회하지 않는다.
- 원문 대사는 순서 있는 `source.literal_ids`, 이름 위치는 원문 기준 `start/end`와 `ref`로 연결한다.
  같은 원문 이름의 가짜/진짜 인물은 사건 근거로 구별한다. 보존 원문을 개명 목적으로 수정하지 않는다.
- `source_exact`는 보존 원문이고 표시명 치환 읽기본은 `source_adaptation`이다.
  새 산문·심리·행동·공간·대사는 `provenance.origin: authored`와 이유를 남긴다.
  고정 설정은 상위 사전에 완전한 추가 메타데이터로 등록한다. `authored_fields`를 원작 사실로 승격하지 않는다.
- 원작 연결 판본은 모든 원문을 보존한다. 반복·빈 문구·배타 응답·무작위 시험·재방문·메타 서사·
  UI/파일명/제어 문자열을 버리지 않는다. 조건별 원문을 단일 정사로 합치거나 미정 동적 변수를 지어내지 않는다.
- 보드 배열은 편집 제안이다. 내부 `materials/quests.json#/route_edges`의 강제·병렬·선택·이탈 조건을
  우선한다. 입구·문 이동 연결을 정정하면 내부 코드 근거와 해석 메타데이터를 남긴다.
- 원고와 `*.continuity.json`을 함께 편집한다. 등장인물·들은 증언·모르는 사실·실제 소지품·기술·
  상태 변화·필수 원문·다음 파일 인계를 검사한다. 방문하지 않은 정보와 아이템을 자동 부여하지 않는다.
- 집필에는 경로별 필터된 카드를 사용한다. 전편 카드·관계·보드·작가용 원문 판본을 독자 HTML에 싣지 않는다.
  미래 사건으로 과거 장면을 먼저 열지 않는다. 독자 HTML의 제목도 현재 장만 전달한다.
- 새 원고는 `outline/draft`, 사건은 `proposed`다. 구조 검사를 접근 조건·산문 의미·모든 분기의 증명으로
  표현하거나 자동 승인하지 않는다. 일부 재집필을 퀘스트 전체 완성으로 표시하지 않는다.
- `previews/`와 원작 연결 생성 JSON은 읽기 전용이다. 수동 출력 변경을 보존하고 입력으로 옮긴 뒤 재생성한다.

## 변경 후 검증

- `tools/writing.py validate`, `export`, `export --check`와 상위 지침의 전체 검사를 실행한다.
- 실제 분기 변경은 `tools/branch_system.py validate`, 원작 연결 변경은
  `tools/source_story.py validate`, `export --check`도 실행한다. 명령은 `novel/` 기준이다.
