# 새 집필 작업

상위 `novel/AGENTS.md`를 따른다. 설정과 보존 원문은 상위 사전을 참조하고,
스토리보드·새 본문·퀘스트별 사건 기록은 이 폴더에 작성한다.

- 공용 `templates/`를 이용해 챕터별 큰 이야기 → 검토·다듬기 → 의미 있는 분기점 → 장면 → 본문
  순으로 작성한다. 전체의 세부 문장을 미리 확정하지 않는다.
- 큰 이야기 초고는 `storyboard/chapter-stories.json`, 공용 양식은
  `templates/chapter-stories.template.json`이다. 네 줄거리 문단·장별 질문·감정 변화·
  다음 장으로 향하는 이유를 먼저 작성한다. 각 장은 중앙 구성의 `chapter_id`와
  모든 `beat_refs`를 참조하고 제목을 복제하지 않는다. 새 연결·감정은 창작 표시한다.
  원작 조건과 공개 시점은 `continuity_limits`에 두고 줄거리를 검증 설명으로 채우지 않는다.
  논리적 메인 흐름 단계에서는 상황·목표·수행·결과·다음 행동을 먼저 쓴다.
  `source_section_refs`로 해당 장의 원작 연결 구간을 참조하고, 설명을 들은 시점과
  실제 능력·계급·열쇠를 얻은 시점을 분리한다. 선택 방문의 메인 채택은 편집 추가로
  메모하며, 선택지·감각 묘사·구체 전술로 인과의 빈칸을 가리지 않는다.
  작가 전용 전편 스포일러이며 독자용 HTML에 통째로 직렬화하지 않는다.
  분기·상세 집필은 별도 단계다. 성공하는 주 시나리오 초안은 실패·도주·배타 대사를
  삭제하거나 모든 경로를 정사로 확정할 권한이 아니다. 기존 첫 챕터 원고를 덮어쓰지 않는다.
- 원작 우선 연결 판본은 `storyboard/source-connected.plan.json`의 구간별 원문 선택과
  전후 산문으로 편집하고 `source-connected/` 및 `previews/source-connected.html`을 생성한다.
  **기존 원문이 모두 있어야 한다.** 문구 발생 ID·출력 사건·장면을 전체 스냅샷과
  대조하며 반복·빈 문구·배타 응답·무작위 시험·재방문·메타 서사도 삭제하지 않는다.
  UI·파일명·제어 문자열은 부록으로 구별하되 버리지 않는다. 조건별 원문이 함께
  있다는 이유로 한 경로에서 모두 발생한 것으로 쓰지 않는다. 원문과 이름 각색을
  분리하고 동적 변수의 미정 값을 임의로 채우지 않는다. 읽기 배열은 원작 강제 순서가 아니다.
  입구·문 이동 등 연결의 정정은 내부 원문 코드 근거와 해석 메타데이터를 남긴다.
  생성 JSON을 직접 편집하거나 수동 편집된 출력을 강제로 덮어쓰지 않는다.
  `python3 tools/source_story.py validate`와 `export --check`도 실행한다.
- 본문, 대사, 선택지, 제목의 이름·장비·마법·지명은 **구조화된 `ref`**로 쓴다.
  `characters/protagonist` 같은 ID는 이름 변경으로 바꾸지 않는다.
  `reference/names.json`의 집필 이름을 문자열로 본문에 복사하지 않는다.
  `reference_text: true`를 끄거나 문자열 치환으로 검사를 우회하지 않는다.
- 표시명 변경은 `reference/names.json`에서 관리하고 인물/참조 자료를 재생성한다.
  원작 이름·음역·`materials/`의 보존 문자열은 이름 변경을 위해 수정하지 않는다.
- 원문 대사는 발생 ID의 순서 있는 `source.literal_ids`로 참조한다. 이름 위치에는
  원문 문자열 기준 `start`/`end`와 `ref`를 연결한다. 원문 이름이 동일한 가짜/진짜
  인물은 사건 근거로 구별하고 이름만 보고 합치지 않는다.
- `source_exact`는 보존 원문을 뜻한다. 표시명으로 치환된 읽기본은
  `display_origin: source_adaptation`이며 원작 한국어 대사였다고 주장하지 않는다.
- 새 연결 서사·감정·행동·공간·대사는 `provenance.origin: authored`와 이유를 기록한다.
  원작에 없는 고정 인물/장비 설정은 상위 사전에 완전한 추가 메타데이터를 등록한다.
  보드의 `authored_fields`는 새 감정선·연결 제안의 표시다. 원작 사실로 승격하지 않는다.
- 보드의 배열은 집필 제안이다. 원작 `materials/quests.json#/route_edges`의 강제 조건,
  병렬 목표, 선택 동료·이탈, 접근 미확정 경로를 우선한다. 후보 인물/공개 사건 목록은
  그 인물의 영입이나 정보의 자동 공개를 의미하지 않는다.
- 원고와 `*.continuity.json`을 함께 편집한다. 등장 인물, 들은 증언, 모르는 사실,
  상태 변화, 원문 필수 블록과 다음 파일 인계를 검사한다. 사전의 장비 참조는 소지품이 아니다.
- 공개 전에는 인물 카드 마스터나 전편 보드를 프롬프트/독자 화면에 통째로 넣지 않는다.
  `writing.py preview`의 경로별 필터를 쓰며 미래 사건으로 과거 장면을 먼저 열지 않는다.
- 새 원고는 `outline`/`draft`, 새 사건은 `proposed`로 둔다. 구조 검사를 통과했다고
  원문의 접근 조건, 산문의 의미, 모든 분기가 검증되었다고 주장하거나 자동 승인하지 않는다.
- **기본 집필 작업량은 한 번에 한 소편이다.** 퀘스트는 큰 흐름의 단위이고,
  실제 집필·문체 검토 단위는 `episodes/`에 정의한 장면 묶음이다. 사용자가
  여러 소편을 명시적으로 요청하지 않으면 한 소편을 쓰고 피드백을 받은 뒤 이어간다.
  긴 소편은 공백 포함 약 3,500~6,500자를 출발 목표로 하되 반복 문장으로 채우지 않는다.
- 선택형 첫 챕터는 `interactive/chapter01.json`에서 기존 긴 원고를 참조해 보충한다.
  이름/무기를 직접 쓰지 않고 참조 ID를 사용하며, 실제 동행+현재 장비+역할 경험을
  함께 검사한다. 지역 방문·영입 경험·현재 동행·일회성 아이템·임무 단계를 구별한다.
  다음 챕터는 경로 인계를 이어받고 방문하지 않은 증언/아이템을 자동 부여하지 않는다.
  원작 발생 ID의 대사/선택 라벨은 조건별 반영표로 누락을 검사한다. 자동 이동도
  경로 선택 ID로 남기고 반복 방문/중복 보상/무한 루프를 막는다. 원작 미확정 접근과
  새 동료·새 영입법·탐방 횟수 제한은 반드시 창작 추가로 표시한다.
- 감각·행동·대화와 장면의 작은 변화를 충분히 펼친다. 인물의 미정 설정을 지키기 위해
  산문에 “확정하지 않는다”, “허가는 획득이 아니다” 같은 작가용 검증 설명을 반복하지
  않는다. 검증·보류 이유는 메타데이터와 연속성 메모에 둔다.
- 소편 목록은 본문의 파일·장면 ID를 참조한다. 같은 본문을 새 JSON에 복사하지 않는다.
- **선택은 장면의 서사를 읽은 뒤 주인공이 행동을 정하는 순간에 둔다.** 인사 방식,
  상태 조회, 대사 한 줄마다 선택지를 만들지 않는다. 선택 전후의 행동·대화·반응을
  충분히 쓰고, 클릭만 늘리는 관찰 메뉴는 자연스러운 서술/자동 연결로 바꾼다.
  매번 모든 선택지를 순회하게 하지 않는다. 하나의 경로로 앞으로 흐르는 구성을
  기본으로 하고, 자유 탐방이나 되돌아보기는 장면상 이유가 있을 때만 제한적으로 쓴다.
  원작의 배타 대사를 자동 배치할 때는 두 조건 모두 도달 가능하게 보존하고,
  창작 연결 조건을 표시한다. 자동 연결은 경로 ID에는 남기되 독자의 결정인 척 쓰지 않는다.
  재집필한 소편과 여전히 짧은 구조 초고인 소편의 상태를 구분하고, 일부 재집필을
  퀘스트 전체의 완성으로 표시하지 않는다.
- **의미 없는 응답은 분기로 만들지 않는다.** “아니오 → 다시 생각 → 원래 자리”,
  단순 재인사·같은 정보 재확인·응답 한 줄 뒤 돌아가기만 하는 우회는 연속 산문으로
  합치거나 자동 연결한다. 내부 확인 플래그 하나를 바꾸는 것만으로 선택의 의미가
  생겼다고 주장하지 않는다. 독자의 선택은 실제 행동·접근법·증언 경험·동료·장비·
  후속 반응 중 무엇이 달라지는지 설명할 수 있어야 한다. 읽기 진행 버튼과 서사적
  분기를 구별하고, 자동 연결을 “선택:”으로 표시하지 않는다. 원문 짧은 응답을 없애지
  않고 대화 맥락을 보충하며, 배타 응답을 재배치할 때에는 서로 다른 질문/시점임을
  산문으로 분명히 하고 창작 각색 메타데이터를 남긴다. 필수 본줄기는 그대로 지킨다.
- **메인 스토리는 선택지가 아니라 필수 본줄기다.** 챕터마다
  `storyboard/chapters.json`에서 제목·원문 묶음·필수 핵심 사건부터 정하고,
  `templates/chapters.template.json`을 공용 양식으로 사용한다. 큰 구성을 먼저 검토한
  뒤 장면을 나누고 한 소편씩 집필한다. 큰 구성의 메인 장과 핵심 사건은 모두 필수다.
  병렬 목표는 둘 다 필수로 유지하되 순서를 강제하지 않는다. 원작 선택 방문을 메인
  사건으로 채택했다면 소설용 추가로 표시한다. 개별 교류·영입·시설 이용은 별도 조건이다.
  미집필 장은 `outline_only`, 실제 장면 참조는 `null`로 두고 거짓 완성/실행 표시를 하지
  않는다. 제목은 중앙 구성에서 참조하며 독자 HTML에는 현재 장 제목만 전달한다.
  `templates/main-story.template.json` 형식으로 장면 ID의 순서와 첫 방문 필수 블록 ID를
  선언한다. 첫 챕터는 `interactive/chapter01.json#main_story`가 기준이다. 성주 접견·
  의뢰·핵심 확인·보고 같은 필수 사건을 선택 탐방/동료 영입 여부에 묶지 않는다.
  선택 분기는 다음 본줄기 이전에 합류해야 하며 중간 종료·후속 장면 바로 가기를
  만들지 않는다. 공유 장면에 다른 시점의 출구를 붙일 때는 임무 단계 조건도 붙인다.
  자동 연결도 본문을 실제로 표시하고, 상태 값만 올려 읽은 장면을 대체하지 않는다.
  첫 방문 필수 블록은 선택 경로에서 숨길 수 없다. 재방문의 요약/조건별 반응은
  허용하되 첫 방문 표시 기록은 경로로 재구성한다. 필수 목록의 변경은 편집 판단으로
  검토하고, 구조 검증을 실제 독자의 읽음이나 산문 의미의 증명으로 표현하지 않는다.
- `previews/`는 읽기 전용 생성물이다. 변경 후 `python3 tools/writing.py validate`,
  `python3 tools/writing.py export`, `python3 tools/writing.py export --check`와
  상위 지침의 테스트를 실행한다. 생성된 HTML에서 집필하지 않는다.
