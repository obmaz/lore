# 장별 곁가지 모험

집필 원본은 [series.json](series.json), 형식은 [스키마](../side-stories.schema.json)입니다.
15장에 두 개씩, 총 30개 선택 이야기를 둡니다. 6개는 그 만남에서 완결되며 나머지는 이후 장면에 여운이 이어집니다.
1·4·7·11·14장의 두 번째 곁가지에는 참여 후 두 해결 방법을 고르는 중첩 선택이 있습니다.
모두 `origin: authored`,
`metadata.addition: true`, `status: proposed`인 창작 초고입니다. 설정·집필 규칙은
[상위 AGENTS.md](../AGENTS.md)를 따르며 이 문서는 파일 역할과 사용법만 안내합니다.

[제작실에서 선택하며 읽기](https://obmaz.github.io/lore/novel/studio/#/reading?document=side-adventures.html).
기존 `paper-draft` 본줄기를 고정하고 곁가지와 중첩 해결 방법만 선택하는 작가용 시범입니다.
본줄기는 소단락 주요 내용이며 완성 장편 본문이나 원문 대사 전체 판본이 아닙니다.
원문 전체는 기존 원작 연결 판본에 보존하고, 공개 `/novel/` 첫 장 독자판은 그대로 둡니다.

## 연결과 기억

`anchor_unit`의 주요 내용을 읽은 뒤 선택하고, 그 소단락의 필수 결과를 거쳐
원래 다음 소단락으로 합류합니다. `reaction_unit`은 이후 선택이 이어지는 문단이며 몇 장 뒤를 가리켜도 됩니다.
`reaction_unit: null`은 그 장면에서 완결되는 이야기입니다. `on_participate`·`on_skip`을 바로 마무리로 읽고
후속 문단과 영향선을 만들지 않습니다. 중첩 선택이 있는 완결형은 선택한 방법의 `reaction`을 바로 마무리로 읽습니다.
1→3, 4→6, 7→9, 11→13, 14→15장의 중첩 분기는 선택 방법별 행동이 후속 장면에서 달라집니다.
9장은 두 봉인 완료 뒤, 15장은 원작 적의 마지막 작별과 떠남 뒤에만 곁가지를 둡니다.

각 참여·지나침은 자기 `side.<id>` 불리언 하나만 변경합니다.
중첩 선택은 부모의 참여가 참일 때만 열리고, 자기 `side.<id>.approach` 불리언만 변경합니다.
첫 해결 방법은 거짓, 두 번째는 참이며, 부모가 거짓인 초기 상태는 해결 경험으로 읽지 않습니다.
본줄기 동료·장비·능력·지식·
열쇠·봉인·이동 조건·진상·필수 사건은 변경할 수 없습니다. 후속 문단은 선행 소단락 방문과
자기 기억만 확인합니다. 거절한 사람이 보지 않은 해결 결과를 알았다고 쓰지 않습니다.
무명 조우 인물은 해당 국소 이야기의 역할이며 새로운 동료가 아닙니다.
인물·무기 이름은 기존 참조 ID로 쓰고, 장비가 달라지는 본줄기 개편 시 무기 사용 산문을 재검토합니다.

## 중첩 선택의 편집 구조

`approach`는 선택 항목입니다. `prompt`와 두 `options`를 쓰며, 각 항목은
안정된 `id`, `label`, `body`, `reaction`을 가집니다. 창작/공개 메타는 부모 이야기에서
상속합니다. 효과·동료·본줄기 조건을 임의로 주입하는 필드는 허용하지 않습니다.

```text
작은 부탁을 만남
├─ 참여 → 도입 → 해결 방법 A / B → 해당 방법의 결과 → 필수 본줄기
│                                              └→ 이후 소단락의 해당 경험 문단
└─ 지나침 → 보지 않은 결과는 모름 → 필수 본줄기 → 지나친 경험 문단
```

중첩이 없는 곁가지는 기존 두 갈래 형식 그대로입니다. 실행 입력에는 부모가 지나친 경우
`/bypass` 자동 연결을 둬 막힘을 방지하지만 수동 경로·독자 선택 버튼에는 넣지 않습니다.
기술 그래프와 조건 JSON에는 실행 이력 확인을 위해 남깁니다. 제작실 그래프의 질문 상세에는
독자가 고르는 실제 방법 두 개만 표시합니다. 제작실의 조회는 실제 독자 상태를 변경하지 않습니다.
시범 화면은 같은 소단락에 곁가지가 둘 있어도 순서대로 표시하고, 미선택 부모 또는 해결 방법이
남으면 다음 장으로 넘어가지 않습니다. 이전 장 조회는 선택 결과를 변경하지 않습니다.

## 파일 역할

- `series.json`: 제목·질문·두 선택 본문·후속 문단·선택적인 중첩 해결 방법·창작 메타의 유일한 편집 입력.
- `reader.js`: 오프라인 선택 시범의 화면 동작. 다음 장은 현재 선택 뒤에 열립니다.
- `generated/runtime.plan.json`, `flow.plan.json`: 기존 분기 정의와 새 곁가지를 결합한 읽기 전용 실행 입력.
- `generated/flow.graph.json`, `flow.md`, `flow.html`: 핵심 6개 + 참여 30개 + 중첩 5개 결정의 결합 그래프.
  실행 옵션 89개 중 5개는 자동 우회이며, 수동 선택 후보는 84개입니다.
- `generated/linear-editions.json`: 기본 본줄기에서 전부 참여/전부 지나침인 두 출판 배열 예시.
- `generated/coverage.json`: 검사의 범위와 미승인 상태. `manifest.json`은 입력·출력 무결성 기록.
- `generated/side-adventures.html`: 제작실에 포함되는 선택형 시범. 생성 파일은 직접 편집하지 않습니다.

원래 `branches/series.json`, 큰 구성·소단락 JSON, 원문은 수정하지 않고 컴파일합니다.
원래 출판용 핵심 판본도 유지하며 제작실에서 결합 그래프와 세 가지 배열 예시를 함께 봅니다.

## 검증과 갱신

`novel/`에서 실행합니다. 게임 수정·실행·빌드는 없습니다.

```sh
python3 tools/side_stories.py validate
python3 tools/side_stories.py replay --side-mode take
python3 tools/side_stories.py replay --side-mode skip
python3 tools/writing.py export
python3 tools/writing.py export --check
python3 tools/side_stories.py export --check
```

원래 96개 핵심 경로 각각에 전부 참여·전부 지나침을 대조하고 혼합 경로 하나를 추가해
각 중첩의 두 번째 방법을 고른 추가 5개까지 198개 대표 경로에서 본줄기 문단·88개 단위·
44개 필수 사건·핵심 상태가 같은지 확인합니다. 중첩의 첫 방법·두 번째 방법·지나침의 후속 반응도 대조합니다.
이론상 전체 조합은 `96 × 2^25 × 3^5 = 782,757,789,696`개지만 전부 열거한 검사가 아닙니다.
자기 기억만 쓰는 컴파일 제약과
본줄기 투영 검사를 함께 사용합니다. 산문 의미·원작 해석·실제 독서·출판 승인을 자동 증명하지 않습니다.
