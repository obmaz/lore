# 소단락 분기 시스템

`series.json`이 실행 입력이다. 소단락의 설명 메모가 아니라 **조건·상태·선택 결과·합류를
실제로 재생하는 작가용 JSON**이다. 형식은 `../branches.schema.json`, 공용 결정 예시는
`../templates/branch-decision.template.json`, 실행 도구는 `../../tools/branch_system.py`다.
88개 소단락의 주요 내용은 `../storyboard/chapter-subsections.json`에서 참조하며 복제하지 않는다.

현재는 6개 결정·14개 선택지·96개 완주 경로다. 분기를 붙인 후보는 4개 소단락이고,
9장의 병렬 순서 선택을 별도로 구현했다. 같은 출발 소단락에 준비와 동행 결정을 순서대로 둔다.
나머지 25개 후보는 미구현이며 검사 결과에 ID를 남긴다. 실행 구조와 선택 뒤 주요 내용은
있지만 장편 본문·모든 원문 대사의 새 런타임 반영은 아직 아니다.

## JSON의 역할

| 필드 | 관리하는 내용 |
| --- | --- |
| `state_definitions` | 자료형·초깃값·사전 ID·값 범위·쓰기 권한 |
| `party_contract` | 현재 동행·선택 동료 한 자리·실제 소유·장착자 |
| `unit_rules` | 소단락 진입 조건·필수 사건의 상태 변화·필요한 공통 내용/제목 각색 |
| `decisions` | 어느 소단락에서 어떤 선택을 하고 어디로 합류하는지 |
| `options[].when` | 기존 조건식의 `all/any/not`, 비교·집합 포함 조건 |
| `options[].participants` | 역할을 맡을 인물의 실제 동행과 필요한 현재 장비 |
| `options[].effects` | `set/add/remove/increment`로 적용할 원자적 변화 |
| `options[].body` | 그 선택을 한 경로에서만 읽는 주요 내용 |
| `reactions` | 앞선 단위의 실제 경험·현재 동행·장비에 따른 후속 이야기 |
| `parallel_orders` | 병렬 목표의 블록 순열. 두 목표를 모두 거치는 순서만 허용 |

예를 들어 준비 선택은 실제 장비 지급과 현재 장착에 영향을 줄 수 있고, 동행 전 대화는
이후 함께 걷는 문단을 바꾼다. 부상자 지원의 역할과 피난처 준비 역시 다음 장면의 반응에
이어진다. 상태 조회를 선택으로 꾸미거나 모든 선택을 반복해서 보게 하는 구조가 아니다.

효과는 기존 `story_continuity.matches/apply` 연산을 공유한다. 이름·무기는 표시 문자열이
아니라 참조 ID로 저장하고 본문에는 구조화된 `ref`를 쓴다. 주인공의 초기 무장은 미지정이며,
무기고에서 기본 무기를 받는 경로는 새 집필 설정으로 표시했다. 기존 첫 장의 초기 상태나
원작 게임을 바꾼 것이 아니다. 역할 분기는 실제 동행 인물과 필요한 장비를 함께 검사한다.

## 필수 본줄기와 상태 인계

공통 주요 내용을 표시한 뒤 선택 결과와 반드시 일어나는 완료 내용을 이어 붙이고 해당 소단락의 필수 사건을 완료한다.
일반 분기는 다음 소단락 전에 합류한다. 9장은 선택한 순서로 두 탐색 블록을 실제로 읽고,
둘 다 완료한 뒤 합류한다. 다음 장을 선택 대상으로 삼거나 한쪽 완료만으로 문을 열 수 없다.

`authority: main`의 열쇠·봉인·필수 지식·계급은 해당 본줄기 사건에서만 기록한다.
분기 효과가 미래의 진상이나 이동 조건을 선지급하면 거부한다. 지식 상태는 설명·증언·기록을
접한 경험이지 그 말이 객관적 진실이라는 판정이 아니다. 계급 변화도 현재 일행의 경로 상태이며
고정 인물 카드의 직업이나 죽은 인물의 부활로 바꾸지 않는다.

동료 영입 경험과 현재 동행은 따로 기록한다. 동료 자리가 차 있으면 또 다른 인물을 끼워 넣지
않는다. 실제 장비가 없거나 이미 떠난 인물이면 그 역할·후속 반응은 나오지 않는다.
효과 묶음은 복사본에서 적용하고 자료형·소유·장착·동료 자리 조건을 모두 통과할 때만 확정한다.
같은 소단락을 재방문하지 않으므로 같은 영입·장비 지급을 반복하지 않는다.

가능한 경로가 하나뿐이면 자동 처리하고 독자의 선택으로 표시하지 않는다. 수동 선택이
필요한 지점에서만 멈춘다. 모든 소단락·필수 사건이 끝나야 완료 상태가 된다.

## 실행과 저장

`novel/` 안에서 실행한다. 게임·서버·빌드가 필요 없다.

```bash
python3 tools/branch_system.py validate
python3 tools/branch_system.py replay --summary
python3 tools/branch_system.py replay --summary --route prepare/self company/leave aid/together
python3 tools/branch_system.py replay --summary --route prepare/armory company/talk_join aid/cook seal_order/muddy_first shelter_prepare/food
```

`replay`는 첫 결정부터 순서대로 처리하고 다음 결정의 선택 가능 ID·현재 상태·이력·필수 사건을
돌려준다. `--summary`는 주요 내용 이력만 생략한다. Python에서는 `BranchSession.choose`,
`save`, `restore`를 쓴다. 저장 JSON에는 버전·입력 지문·수동 선택 ID 목록만 있고, 상태나
진도를 받지 않는다. 자동 선택·영입·보상·읽은 단위는 처음부터 재생해 복원한다.
다른 판본·미래 선택·반복 선택·완료 뒤 선택·임의 상태를 끼운 저장 파일은 거부한다.
입력 지문은 경로가 아니라 자료·참조·실행 코드로 계산해 독립 폴더로 옮겨도 유지된다.

검사는 선언한 분기를 모두 탐색해 96개 완주 경로와 선택지 도달·필수 단위·조건을 확인한다.
탐색 한도를 넘으면 검증 완료라고 보고하지 않는다. 이 검사는 산문의 의미·원작의 모든 접근
조건·독자가 실제로 읽었는지·장편 본문의 완성을 증명하지 않는다.

## 기존 독자 화면과의 구분

`../interactive/chapter01.json`과 독자용 `/novel/` 첫 장은 그대로다. 두 시스템은 같은 조건·효과
연산을 쓰지만 상태 이름과 저장 판본은 다르다. 새 분기를 독자 화면에 적용할 때는 원문 발생 ID
반영표·경로별 공개·연속성 계약과 상태 변환을 먼저 검증해야 한다. 지금 작가용 전편 JSON을
독자 화면에 통째로 넣거나 기존 저장 파일을 자동 승격하지 않는다.

수정 후 `branch_system.py validate`, `writing.py validate`, `writing.py export`,
`writing.py export --check`와 상위 지침의 전체 검사를 실행한다. 생성한 작가용 안내는
`../previews/branch-system.html`, 경로 결과는 `../previews/branch-system-report.json`에 있다.
