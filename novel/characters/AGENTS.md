# 인물 카드·관계·스포일러 지침

- 상위 `novel/AGENTS.md`를 함께 따른다. 원문에 없는 관계·동기·복선 표현은 반드시
  `origin`과 `metadata.addition/kind/note`로 표시한다. 추론과 창작은 `proposed`다.
- `registry.json`은 전편 진상이 들어 있는 **작가 전용 원본**이다. 접근 권한을
  암호화하는 파일이 아니므로 원본을 공유하면 스포일러도 공유된다. 독자용 소개와
  일반 집필 입력은 공개 필터를 통과한 카드만 사용한다. 미래 인물 명단도 공개하지 않는다.
- 원문 관계 분석과 편집용 공개 정책은 `relationships.analysis.json`에서 수정한다.
  관계 ID는 안정적으로 유지하며 대상 인물 ID, `relation_type`, `truth_type`,
  `claimant`, 원문 근거와 `branch_condition`을 기록한다. 관계 역방향은 원문이
  허용하는 경우에만 만든다. 다른 장면에서 같은 전투 템플릿을 썼다고 동일 인물로 합치지 않는다.
- `testimony`는 누가 그렇게 말했다는 사실이며 진상이 확정됐다는 뜻이 아니다.
  `document_claim`은 예언서 같은 문서의 설명이다. 목격 사건은 `source_event`,
  해석은 `inferred`, 새 관계 설정은 `authored`로 구분한다. 신화·장르 상식을 원작에 덧붙이지 않는다.
- 공개 시점은 챕터/퀘스트 번호로 자동 추정하지 않는다. 실제 선택 경로에서 해당
  원문 장면을 서술한 사건의 `reveals`에 체크포인트를 연결한다. 앞선 선택으로 그
  사건을 건너뛰었으면 공개하지 않는다. 공개 체크포인트 자체도 편집자가 추가한 정책이다.
- 관계의 `disclosure`에는 `spoiler`, `after_events`, `foreshadowing`,
  `policy_metadata`가 필수다. `after_events`는 나열된 체크포인트 중 하나가 발생한
  뒤에만 열리는 조건이며, 비어 있는 카드 공개 목록은 **항상 비공개**이지 공개가 아니다.
- 공개되지 않은 관계의 대상·유형·설명·비밀을 암시하는 ID/제목을 집필용 카드로
  전달하지 않는다. 정체가 비밀인 인물은 `public_id`와 `public_display_name`을
  중립적으로 정한다. 원어 이름·음역·별칭에서도 진상이 새지 않는지 검토한다.
- 복선은 `foreshadowing`의 검토된 `claim`만 전달한다. 복선에도 허용 시점과
  추가 메타데이터를 둔다. "아직 X의 정체를 말하지 마라"처럼 답을 담은 경고도
  일반 집필 프롬프트에 넣지 않는다. 비공개 설명을 즉석에서 요약해 복선으로 만들지 않는다.
- 숨긴 관계가 `source_facts`, 성향·목표, 원문 발췌·비고·장비 참조에 중복되어
  누출되지 않는지 검사한다. `source_facts`는 `fact_after`에 명시한 항목만 공개하며
  새 항목은 기본 비공개다. 원문 발췌·별칭·작가 비고는 공개 카드에 통째로 넣지 않는다.
- `after_events`로 여는 생애/성향/장비 묶음의 내용을 바꾸면 공개 경계도 다시
  검토한다. 숨길 내용을 기존 공개 성향 배열에 몰래 추가하지 않는다.
- 관계 공개는 등장인물이 지식을 얻었거나 영입·배신·사망이 실제로 발생했다는
  뜻이 아니다. 지식은 `knowledge_gained`, 현재 동료/생사는 경로 상태와 사건에
  기록한다. 조건부 관계는 조건이 성립한 경로에서만 과거 사실로 사용한다.
- 초안 경로의 공개는 잠정 미리보기다. 독자에게 확정 공개하려면 원고·사건·연속성
  승인이 필요하다. 정책/관계 수정 시 인물/목록 revision과 승인 해시, 의존 장면을 검토한다.
- 재생성은 `python3 tools/build_reference.py`로 한다. 수동 출력 수정이나 기존
  `reference/analysis.json`의 옛 `relationships_additions`를 묵시적으로 무시하지 않는다.
  새 파일의 관계 분석 형식으로 명시적으로 옮긴다.
- 검증에서 공개 전/공개 후, 사건을 건너뛴 경로, 원문 발췌를 통한 누출, 내부 ID의
  누출과 새 창작의 메타데이터를 검사한다. 산문상의 암시 강도는 사람이 최종 검토한다.
