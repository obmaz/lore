# 집필 참조 사전

게임 파일 없이 `novel/` 내부 JSON만으로 조회·검증·재생성한다.

- [equipment.json](equipment.json): 무기 10종(맨손 포함), 방패 5종, 갑옷 5종.
  원작 이름·상점 가격·기본 위력·직업 제약을 보존한다. 황금의 방패/갑옷의 발견 표기와
  장착 근거도 금제 장비 항목에 넣었다. 화염검의 속성 피해는 미상이다.
- [abilities.json](abilities.json): 직접 공격 12종, 간접 공격 6종, 회복 14종,
  현상 마법 8종, 초자연력 5종. 효과·SP/ESP·실패/저항·사용 조건의 근거를 둔다.
- [bestiary.json](bestiary.json): 적 템플릿 75종. 원어 이름·한국어 음역·원작 전투 수치와
  관련 인물 ID를 포함한다. 원작의 Gagoyle/Wivern 등 철자도 임의로 교정하지 않는다.
- [analysis.json](analysis.json): 검토한 음역·원작 역할 요약·성격 해석의 편집 입력.
- [metadata.schema.json](metadata.schema.json): 항목별 출처·추가·미상 메타데이터 규약.

| `origin` | `metadata.kind` | 의미 |
| --- | --- | --- |
| `source_exact` | `none` | 원작 값 그대로, 근거 필수 |
| `source_adaptation` | `none` | 원작 근거를 요약, 근거 필수 |
| `inferred` | `interpretation` | 해석·추론을 추가함. `addition: true`, `proposed` |
| `authored` | `new_setting` | 원작에 없는 창작. `addition: true`, `proposed` |
| `authored` | `transliteration` | 집필용 한국어 음역 표기 추가. 의미 번역 아님 |
| `unknown` | `unknown` | `value: null`, `status: unknown`. 미상으로 보류 |

나이·직업·성격·관계·장비 효과·마법 효과를 새로 만들 때 같은 규칙을 쓴다.
새 음역과 새 스토리 설정을 구분하므로 이름 표기만 바꿔도 새로운 생애 설정을
추가한 것으로 혼동하지 않는다. 이름이 원래 한국어인 마법/무기는 영어 이름을 지어내지
않고 원문 한국어를 그대로 보존한다. `마법의 햇불` 같은 원문 표기도 보존한다.

## 수정과 재생성

`analysis.json`을 편집한 뒤 `python3 tools/build_reference.py`를 실행한다.
출력 4개 파일의 기준 해시는 `generated_manifest.json`에 있다. 출력 파일을 직접
편집했으면 도구는 덮어쓰기를 거부한다. 먼저 그 수정을 분석 입력의 완전한 claim으로
옮기고, 편집 전 출력 버전을 복원한 뒤 재생성한다. 자동 강제 덮어쓰기 옵션은 없다.
원작 마법 효과는 내부 스냅샷 분석 결과와 생성 도구의 추출 규칙으로 관리한다.

생성 도구는 모든 후보 출력의 스키마·근거·추가 표시·참조 링크를 검사한 다음에만
쓴다. 인물 변경은 인물/목록 revision을 올리고 장면 의존성을 재검토하게 한다.
무기·마법·적 자료도 연속성 승인 해시에 포함되어 변경된 자료를 이전 승인으로
통과시키지 않는다. 반복 실행은 변경이 없으면 같은 파일을 만든다.

## 집필에서의 경계

참조 사전은 작가의 정보이지 등장인물의 현재 지식이나 소지품 목록이 아니다.
경로 문맥은 해당 장면 등장인물의 관련 항목만 `writing_references`에 전달한다.
영입 장비를 항상 가지고 있거나 설명된 마법을 모두 습득했다고 서술하지 않는다.

적 템플릿의 `level`, `special`, `cast_level`은 전투 수치이지 나이·성격·마법 목록의
직접 증거가 아니다. 보스는 같은 템플릿을 이름/수치 변경해서 쓸 수 있다.
원본 75개 레코드는 [enemy_templates.json](../materials/enemy_templates.json)에
원본 바이트와 SHA-256까지 보존했다. 외부 DAT 파일은 조회할 필요 없다.

검증은 누락된 메타데이터, 원작 이름/수치 변조, 존재하지 않는 ID와 근거 위치,
미상/창작/추론의 잘못된 상태를 검사한다. 요약의 의미가 근거에 정말 부합하는지나
완성된 산문의 성격·마법 묘사를 완벽히 판정하지는 못하므로 집필 검토를 병행한다.
